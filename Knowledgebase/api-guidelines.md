# Helix REST API Guidelines

**Owner:** Helix Core API maintainers  
**Audience:** Engineers building or consuming Helix HTTP APIs  
**Last reviewed:** 2026-06-03  
**Status:** Approved  
**Related:** [architecture.md](architecture.md), [authentication.md](authentication.md), [testing.md](testing.md), [logging-and-monitoring.md](logging-and-monitoring.md)

These rules apply to `helix-gateway` and `helix-core-api` version **1.0**. Identity’s public routes under `/v1/identity/*` follow the same error envelope and headers. Internal identity routes under `/internal/*` are not part of the public contract and must not appear in partner OpenAPI.

The source of truth for the public contract is the generated file `helix-api.v1.json` published as a pipeline artifact from `helix-api-ci`. Contract tests in [testing.md](testing.md) fail the build if controllers drift from that document without an approved versioning change.

---

## 1. Base URLs and versioning

| Environment | Gateway base URL |
| --- | --- |
| Production (internal) | `https://api.helix.nordicsystems.internal/v1` |
| Production (partners) | `https://api.nordicsystems.com/helix/v1` |
| Staging | `https://api-stage.helix.nordicsystems.internal/v1` |
| Test | `https://api-test.helix.nordicsystems.internal/v1` |
| Development | `https://api-dev.helix.nordicsystems.internal/v1` |

URI versioning is used (`/v1`). Header `X-Api-Version` currently accepts only `1.0`. Unknown versions return `400` / `UnsupportedApiVersion`. Breaking changes require `/v2` and an ADR; additive JSON fields are allowed in 1.x if they are optional and ignored by older clients.

JSON uses **camelCase**. Dates are **ISO-8601 in UTC** with `Z` suffix (example: `2026-04-11T06:15:00Z`). GUIDs are lowercase hex with hyphens.

## 2. Common headers

| Header | Direction | Requirement |
| --- | --- | --- |
| `Authorization` | Request | `Bearer` token; see [authentication.md](authentication.md) |
| `X-Helix-Tenant-Id` | Request | Required except health/ready |
| `X-Helix-Correlation-Id` | Request/response | Echoed on every response; generated by gateway if missing |
| `X-Api-Version` | Request | Optional, default `1.0` |
| `Idempotency-Key` | Request | Required for `POST /v1/work-orders` and `POST /v1/customers`; UUIDv4, retained 24 hours |
| `Content-Type` | Request | `application/json` for bodies |
| `Accept` | Request | `application/json` |

Responses include `X-Helix-Correlation-Id` and `X-Helix-Service` (`helix-gateway` or `helix-core-api` after proxy). Clients must log the correlation id on failures so on-call can search Application Insights (see [logging-and-monitoring.md](logging-and-monitoring.md)).

## 3. Public endpoints (Helix Core)

Unless noted, all routes require a valid token and tenant membership.

### 3.1 Platform

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| GET | `/v1/health` | Anonymous | Liveness; no dependency checks |
| GET | `/v1/ready` | Anonymous | Readiness; pings HelixCore with 2s timeout |

`GET /v1/health` must stay under 50 ms p95. Successful health calls are excluded from App Insights sampling; failures are never sampled away.

### 3.2 Customers

| Method | Path | Roles | Notes |
| --- | --- | --- | --- |
| GET | `/v1/customers` | All Helix roles | Filter `status`, `query`; paging |
| GET | `/v1/customers/{customerId}` | All | 404 `CustomerNotFound` |
| POST | `/v1/customers` | Admin, Operator, Integration | Idempotent via `Idempotency-Key` |

`customerId` is `uniqueidentifier`. External partner keys belong in `core.Customers.ExternalReference` (string, unique per tenant), not in the URL.

### 3.3 Work orders

| Method | Path | Roles | Notes |
| --- | --- | --- | --- |
| GET | `/v1/work-orders` | All | Filters: `status`, `assetId`, `customerId`, `fromUtc`, `toUtc` |
| GET | `/v1/work-orders/{workOrderId}` | All | 404 `WorkOrderNotFound` |
| POST | `/v1/work-orders` | Admin, Operator, Integration | Creates `Draft`; outbox event `WorkOrderCreated` |
| PATCH | `/v1/work-orders/{workOrderId}` | Admin, Operator, Integration | JSON merge-style document; only listed fields |

Allowed PATCH fields: `status`, `scheduledStartUtc`, `scheduledEndUtc`, `assigneeObjectId`, `priority`, `notes`. Status transitions are enforced in domain:

`Draft` → `Scheduled` → `InProgress` → `Completed`  
`Draft` or `Scheduled` → `Cancelled`

Illegal transitions return `409` / `InvalidWorkOrderTransition`. Completing a work order requires `scheduledStartUtc` not in the future relative to `DateTime.UtcNow` (server clock).

### 3.4 Assets and contracts

| Method | Path | Roles |
| --- | --- | --- |
| GET | `/v1/assets` | All |
| GET | `/v1/assets/{assetId}` | All |
| POST | `/v1/assets/{assetId}/events` | Admin, Operator, Integration |
| GET | `/v1/contracts` | All |
| GET | `/v1/contracts/{contractId}` | All |

`POST /v1/assets/{assetId}/events` body: `{ "type": "Inspection|Alarm|Note", "occurredUtc": "...", "payload": { } }`. Payload size limit is **32 KB**. Larger payloads return `413` / `AssetEventTooLarge`.

### 3.5 Administration

| Method | Path | Roles |
| --- | --- | --- |
| GET | `/v1/admin/tenants` | `Helix.Administrator` only |

Admin routes always bypass membership cache ([authentication.md](authentication.md)).

## 4. Paging, filtering, and limits

List endpoints use cursor-unaware offset paging:

- `page` default `1`, minimum `1`
- `pageSize` default `25`, maximum **100**
- Response envelope: `{ "items": [ ], "page": 1, "pageSize": 25, "totalCount": 0 }`

Do not loop `pageSize=100` as a production export. Exports go through `helix-jobs` (no public HTTP export API).

Rate limits (enforced at `helix-gateway`):

- User tokens: **600** requests/minute per Entra object id
- `Helix.Integration`: **3,000** requests/minute per client id
- Burst: 2× for 10 seconds, then 429

`429` includes `Retry-After` (typically 10–30 seconds), code `RateLimitExceeded`.

## 5. Error envelope

All error responses (4xx/5xx) use:

```json
{
  "error": {
    "code": "WorkOrderNotFound",
    "message": "Work order was not found for this tenant.",
    "correlationId": "c0a80100-0000-4000-8000-000000000001",
    "details": []
  }
}
```

`details` is an array of `{ "field": "scheduledStartUtc", "issue": "..." }` for validation failures (`400` / `ValidationFailed`). Do not put stack traces in `message`. Do not put SQL text in `details`.

| HTTP | Typical code | When |
| --- | --- | --- |
| 400 | `MissingTenantId`, `ValidationFailed`, `UnsupportedApiVersion` | Client input |
| 401 | `Unauthorized` | Token |
| 403 | `Forbidden` | Role or tenant membership |
| 404 | `CustomerNotFound`, `WorkOrderNotFound`, `AssetNotFound`, `ContractNotFound` | Missing entity **in this tenant** (do not leak cross-tenant existence) |
| 409 | `InvalidWorkOrderTransition`, `IdempotencyConflict` | State or idempotency key reuse with different body |
| 413 | `AssetEventTooLarge` | Payload |
| 429 | `RateLimitExceeded` | Gateway |
| 503 | `IdentityUnavailable`, `DependencyUnavailable` | Downstream |

Idempotency: if the same `Idempotency-Key` is replayed with the **same** body hash, return the original `201` payload. If the body hash differs, `409` / `IdempotencyConflict`. Keys are stored in HelixCore `ops.IdempotencyKeys` for 24 hours.

## 6. Idempotency, concurrency, and caching

`PATCH /v1/work-orders/{id}` requires `If-Match` with the ETag from GET. ETag is the SQL `RowVersion` encoded as Base64. Missing `If-Match` returns `428` / `PreconditionRequired`. Mismatch returns `412` / `PreconditionFailed`.

GET list responses are `Cache-Control: private, no-store`. Individual GET-by-id may use `Cache-Control: private, max-age=0, must-revalidate` plus ETag.

## 7. Compatibility and deprecation

Deprecated OpenAPI fields remain at least **two** staging releases. `workOrder.legacyTicketNo` is deprecated as of 1.0.4 (remove no earlier than 1.2); use `externalReference`. Partner HTTP webhooks are not in v1; internal events use Service Bus ([architecture.md](architecture.md)).
